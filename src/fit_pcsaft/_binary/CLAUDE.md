# Binary k_ij fitting (`src/fit_pcsaft/_binary/`)

- **`fitter.py`**: `ard_by_type` (and `data["ard_<type>"]`) is scored at that **returned** polynomial by `_ard_at_coeffs(res, kij_coeffs, kij_t_ref, src)` — failed rows count 100 %, as in vle.py/lle.py; `fit_kij_vle_lle` uses the same helper. Before 2026-10 both reported each source's own order-0 sub-fit ARD.
- **`vle.py`, `lle.py`, `vlle.py`, `sle.py`**: Standalone `fit_kij_*` functions for single-data-type fitting (also used internally by `BinaryKijFitter`). k_ij(T) is always evaluated in kelvin (`T_csv * t_scale`). `_bubble_point` passes `max_iter_outer=30` and every `heteroazeotrope` call `max_iter_bd_outer=30` (feos default 400): a solve that fails otherwise burns ~95 ms against ~0.4 ms for one that converges — mibk/water VLE+LLE fit 6.5 → 2.8 s (2026-10-12), every converged point on the example k_ij grids bitwise unchanged. Validated only on the bundled example systems. The global P-only `fit_kij_vle` (no y1 column, `kij_per_point=False`) takes its Jacobian from feos AD (`feos.Property.bubble_point_pressure_derivatives`, `PcSaftFull`, rows `[m, σ, ε/k, μ, κ_ab, ε_ab/k, na, nb]×2 + k_ij`, `parameter_names=["k_ij"]`) while values stay on the serial solver: a row is trusted only where the AD pressure matches the serial one to 1e-8 relative — AD returns `ok=True` on wrong roots (up to 89 % off on ethanol/water) — and a row that misses falls back to finite differences for the rest of the fit. 19–57 % faster (2026-10-12) on y-stripped ethanol/water and mibk/water copies (no shipped CSV is P-only), coefficients within 1e-6 at orders 0–1; at order ≥ 2 the problem is ill-conditioned and the AD run lands elsewhere at equal or lower cost. `_ard_at_coeffs` scores LLE rows from a cold anchor start (a warm start chained from a far-off k_ij locked one row onto a 21 840 % branch) and blank y1 cells as P-only rows.
- **`vle_lle.py`**: `fit_kij_vle_lle()` — combined VLE+LLE two-stage fitting: fits per-point k_ij independently for VLE and LLE, then fits a single k_ij(T) polynomial to the combined pairs. Standalone only (not available via `BinaryKijFitter`).
- **`henry.py`**: `fit_kij_henry()` — fits k_ij from Henry's law constant data. Component 1 is the solute, component 2 the solvent. Supports `henry_unit="molfrac"` for dimensionless K = y₁/x₁ data (converts via K = H_feos / P_vap_solvent). Standalone only.
- **`_utils.py`**: Shared helpers — `_load_pure_records`, `_build_binary_eos`, `_kij_at_T`, `_apply_induced_association`, `_make_binary_jac_fn`, `_fit_kij_polynomial`. `_apply_induced_association(sites="2B"|"own", epsilon_k_ab=...)`: `"own"` keeps a ketone's declared acceptor-only site; `epsilon_k_ab` is the cross-association parameter (Rehner, Bardow & Gross 2023) — every `fit_kij_*` except `fit_kij_sle`, and `BinaryKijFitter`, forward them as `induced_sites` / `induced_epsilon_k_ab`. The native alternative (2026-09-13): `_build_binary_eos(..., binary_assoc=[{"kappa_ab": ..., "epsilon_k_ab": ...}])` writes the cross pair on feos's `BinaryRecord.association_sites` — applied as-is, no combining rule, even when a pure site carries no parameters (feos's own `rehner2023_binary.json` shape); `fit_kij_lle(binary_assoc=...)` stores it on `BinaryFitResult._binary_assoc`, and every re-prediction from the stored records (`result.py`, `_plot.py`) passes it along. Default `None`, behaviour unchanged. `record_at_T(record, T_K) -> record` is the same pattern for a parameter feos holds constant (a T-dependent σ, e.g. Cameretti & Sadowski 2008's water): `_build_binary_eos(..., T_K=..., record_at_T=...)` applies it to both records and raises `ValueError` without `T_K`; `fit_kij_lle`/`fit_kij_sle` take it, build `eos` at `kij_t_ref`, store it on `BinaryFitResult._record_at_T`, and the LLE anchor flash and SLE curves rebuild at their own temperature. VLE/VLLE/Henry fits and plots raise `NotImplementedError` when it is set. Default `None`, behaviour unchanged.
